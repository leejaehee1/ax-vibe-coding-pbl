# [실습 템플릿 2] Claude Code 바이브코딩 프롬프트 템플릿 5종 & CLAUDE.md 가이드

> **핵심 원칙**: 비전공자가 바이브코딩에서 실패하는 가장 큰 이유는 **"한 번에 너무 많은 것을 모호하게 시키기 때문"** 입니다.  
> **① 계획(Plan) → ② 기본 골격 구현 → ③ 데이터·기능 고도화 → ④ 최소 범위 디버깅 → ⑤ 테스트 검증** 의 5단계 템플릿을 복사해 괄호 `[ ]` 부분만 내 업무에 맞게 수정해 사용하세요.

## 0. 프로젝트 헌장: `CLAUDE.md` 표준 템플릿
프로젝트 폴더 최상단에 `CLAUDE.md` 파일을 만들어 두면, Claude Code가 매번 맥락을 잊지 않고 일관된 품질로 코딩합니다.

```markdown
# 프로젝트명: [부서별 예산 대비 실적(BVA) 자동 분석기]

## 1. 프로젝트 목적 및 사용자
- 사용자: 제조 대기업 [재무팀 과장 (비개발자)]
- 목적: [매월 부서별 예산/실집행 CSV 데이터를 업로드하여 편차와 초과 집행 항목을 즉시 파악]

## 2. 기술 스택 및 실행 환경 제약 (필수 준수)
- 보안 정책이 적용된 Windows 업무용 PC에서 별도 서버/DB 설치 없이 실행되어야 함
- 단일 `index.html` (또는 HTML + JS + CSS) 기반 로컬 웹 애플리케이션으로 구현
- 스타일링: Tailwind CSS (CDN), 차트: Chart.js (CDN), CSV 파싱: PapaParse (CDN)
- 한글 깨짐 방지를 위해 UTF-8 및 EUC-KR/CP949 인코딩 자동 감지 처리 포함
- 모든 금액은 천 단위 콤마(,)와 '백만원' 또는 '원' 단위로 가독성 있게 표시

## 3. 데이터 컬럼 구조 (`sample_data.csv`)
- 컬럼: `[연월, 부서명, 계정과목, 예산액, 실집행액, 전월집행액, 비고]`

## 4. 핵심 기능 (MVP Scope)
1. [CSV 파일 업로드 및 초기 샘플 데이터 자동 로드 기능]
2. [예산 대비 편차(실집행-예산), 소진율(%) 자동 계산 및 100% 초과 항목 적색 강조]
3. [부서별/상태별 필터링 및 임원 보고용 3줄 요약 자동 생성]

## 5. 작업 규칙
- 코드를 수정할 때는 기존에 잘 동작하는 기능을 절대 깨뜨리지 말 것
- 한 번에 하나씩 단계별로 구현하고, 수정 후에는 변경된 부분과 확인 방법을 한국어로 짧게 설명할 것
```

## 템플릿 ① 요구사항 정의 및 개발 계획 수립 (Plan 모드용)
> **언제 쓰나요?**: 첫 코드를 짜기 전, Claude Code에서 `Shift + Tab`을 눌러 **Plan Mode** 로 전환한 뒤 입력합니다.

```text
당신은 제조 대기업 업무 자동화 전문가이자 프론트엔드 웹 개발자입니다.

[업무 배경]
나는 제조기업의 [재무/전략기획/마케팅/세일즈] 담당자입니다.
현재 [매월 각 부서의 실적 엑셀을 취합해 목표 달성률과 이상 항목을 수작업으로 찾는 데 5시간 이상] 걸리고 있습니다.

[개발 목표]
서버나 데이터베이스 설치 없이, 웹 브라우저에서 `index.html`만 열면 바로 작동하는 [예산 대비 실적 분석 웹 도구]를 만들고 싶습니다.

[입력 데이터 구조]
- 파일 형식: CSV 파일 (`sample.csv`)
- 주요 컬럼: [부서명, 계정과목, 예산액, 실집행액, 전월실적]

[핵심 기능 2가지]
1. [CSV 업로드 또는 '샘플 데이터 불러오기' 클릭 시 상단 KPI 요약 카드 4개와 상세 테이블 표시]
2. [소진율 100% 초과 항목을 자동 탐지해 빨간색 배지로 표시하고, 부서별 비교 막대 차트 출력]

[제약조건]
- 비개발자 동료도 직관적으로 쓸 수 있는 깔끔한 대시보드 디자인
- 실제 기밀 데이터 대신 그럴듯한 제조기업 가명 샘플 데이터 30행(`sample.csv`) 함께 생성

아직 코드는 작성하지 마세요.
먼저 1) 생성할 파일 구성, 2) 화면 레이아웃 설계, 3) 3단계 구현 순서, 4) 검증 방법을 한국어로 제안해 주세요.
```

## 템플릿 ② 단계별 핵심 기능 구현 지시
> **언제 쓰나요?**: 템플릿 ①의 계획이 마음에 들면 일반 모드로 전환하여 **1단계부터 순서대로** 구현을 지시합니다.

```text
제안해 준 계획이 좋습니다. 먼저 1단계와 샘플 데이터를 구현해 주세요.

[이번 단계 작업 지시]
1. `CLAUDE.md` 파일을 먼저 생성하여 프로젝트 규칙을 저장하세요.
2. 제조기업 실무에 어울리는 현실적인 샘플 데이터 30행이 담긴 `sample.csv` 파일을 생성하세요.
3. `index.html`을 생성하여 다음 기능을 구현하세요:
   - 페이지 열기만 해도 기본 샘플 데이터가 즉시 화면에 표시될 것 (로컬 CORS 문제없이 내장 데이터 fallback 포함)
   - 상단에 새로운 CSV 파일을 업로드할 수 있는 버튼과 '샘플 데이터 초기화' 버튼 배치
   - 상단 KPI 요약 카드 4개([총 예산, 총 집행액, 평균 소진율, 초과 건수])와 하단 데이터 테이블 표시

구현이 끝나면 내가 브라우저에서 어떤 파일을 열어서 무엇을 확인하면 되는지 알려주세요.
```

## 템플릿 ③ 비즈니스 로직 고도화 및 UI/UX 개선
> **언제 쓰나요?**: 기본 화면이 뜬 후, 내 직무에 필요한 계산 수식·필터·차트·보고서 문구 생성을 추가할 때 사용합니다.

```text
기본 화면과 테이블이 잘 나옵니다. 이제 2번째 핵심 기능인 [이상 항목 필터링 및 자동 요약 브리핑] 기능을 추가해 주세요.

[추가 및 개선 사항]
1. 필터 기능: [부서별 드롭다운 필터]와 ['초과 항목만 보기' 토글 버튼]을 추가해 테이블과 차트가 즉시 연동되게 해주세요.
2. 시각적 강조: [소진율이 100%를 초과한 행은 연한 빨간색 배경과 '초과' 배지]로 눈에 띄게 표시해 주세요.
3. 임원 보고용 자동 요약 박스: 현재 필터링된 데이터를 기준으로,
   - 전체 달성 현황 1줄
   - 가장 편차가 큰 상위 3개 항목
   - 중점 점검 필요 사항 1줄
   을 자동으로 문장으로 만들어주고 [클립보드 복사] 버튼을 달아주세요.

기존에 잘 작동하던 CSV 업로드 기능은 건드리지 말고 유지해 주세요.
```

## 템플릿 ④ 오류 분석 및 최소 범위 수정 (디버깅용)
> **언제 쓰나요?**: 화면이 안 나오거나, 계산 숫자가 `NaN`으로 뜨거나, 버튼이 작동하지 않을 때 사용합니다.

```text
현재 프로젝트에서 다음 문제를 발견했습니다.

[발생한 현상]
- 내가 실행한 동작: [`sample.csv` 파일을 업로드하고 '부서 필터'를 변경함]
- 기대했던 결과: [선택한 부서의 합계 금액과 차트가 업데이트되어야 함]
- 실제 나타난 현상/오류: [합계 금액이 `NaN원`으로 표시되고 차트가 사라짐]
- 브라우저 콘솔(F12) 에러 메시지: [여기에 빨간색 에러 메시지가 있다면 붙여넣기]

[수정 요청 규칙]
1. 오류가 발생한 원인을 비전공자가 이해할 수 있게 2~3줄로 먼저 설명해 주세요.
2. 현재 정상 작동 중인 [전체 레이아웃과 기본 표 출력 기능]에는 영향을 주지 않는 **최소한의 코드 수정안**을 적용해 주세요.
3. 숫자 컬럼에 콤마(`,`)나 빈칸, 문자열이 섞여 들어와도 오류가 나지 않도록 방어 로직을 함께 넣어주세요.
```

## 템플릿 ⑤ 테스트 시나리오 도출 및 엣지 케이스 검증
> **언제 쓰나요?**: DAY 2 후반부 또는 DAY 3 발표 직전, 시연 중 에러가 나지 않도록 최종 점검할 때 사용합니다.

```text
내일 임원 및 동료들 앞에서 5분간 이 MVP를 라이브로 시연할 예정입니다.
시연 도중 당황스러운 오류가 발생하지 않도록 다음 사항을 점검하고 보완해 주세요.

1. 예외 상황(Edge Case) 방어 코드 점검:
   - CSV 파일에 빈 줄이 있거나 금액에 `1,200,000`처럼 콤마가 포함된 경우

   - 한글 인코딩(UTF-8 / CP949)이 다른 엑셀 CSV를 올렸을 때 한글이 깨지는 경우
2. 위 3가지 경우에 모두 에러 없이 안전하게 처리되도록 코드를 보강해 주세요.
3. 내가 발표 전에 직접 클릭하며 확인해 볼 수 있는 [5분 시연 테스트 체크리스트 5항목]을 작성해 주세요.
```
